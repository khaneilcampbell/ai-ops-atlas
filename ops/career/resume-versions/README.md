# Resume Versions

Three foundational versions share **the same facts**. What changes is the angle:
which experience leads, which accomplishments are featured, which projects appear,
and how skills are ordered.

| Version | File | Target positions |
|---|---|---|
| AI Solutions | [ai-solutions.md](ai-solutions.md) | AI Solutions Engineer, Business Solutions Specialist, AI Consultant, Technical Solutions Consultant |
| Enterprise Technology | [enterprise-technology.md](enterprise-technology.md) | IT Engineer, Enterprise Systems Engineer, Technical Operations, Business Technology Engineer |
| Security & Automation | [security-automation.md](security-automation.md) | Security Engineer, Security Automation Analyst/Engineer, SOC Engineer |

Each file is a **strategy**, not a resume. Claude reads it together with your
career database to assemble the base resume for that version, then tailors it
per job. Once you approve a base version, save it as
`private/resumes/base/<version>.docx` so every tailored resume starts from it.

## Shared resume skeleton (ATS-safe)

```
FIRST LAST
City, ST · email · phone · linkedin · github

SUMMARY
EXPERIENCE        (reverse chronological; Employer, Title, Location, Dates)
PROJECTS          (labelled as independent projects)
TECHNICAL SKILLS  (grouped by category)
EDUCATION
CERTIFICATIONS
```

Rules for all versions: single column, standard headings, no tables or graphics,
past tense for past roles, 3-5 bullets for recent roles, one page preferred.
